# DSH 工作流库

已针对 DSH 0.2.2-rc.1 构建的本地插件。通过原生侧栏插槽接入现有 GUI，不修改 app.asar，不运行额外服务器。

## 使用

1. 安装启用后刷新原 DSH 页面，侧栏底部出现「工作流库」。
2. 打开一个已经成功完成任务的普通会话，等待空闲。
3. 点击「提炼当前会话（消耗额度）」，确认发送。模型在该会话生成工作流 JSON。
4. 等待完成，再点击「读取提炼结果」。审阅、校验并保存。也可新建并粘贴 JSON。
5. 以后选择已保存工作流，填写参数，生成提示词预览，确认运行到当前空闲会话。
6. 「导出全部」下载带格式版本的 JSON；「导入」预览并确认保存，不会自动执行。

## 边界

- 这是智能体按模板执行的工作流，不是确定性的历史工具调用重放，也不直接调用多智能体 workflow 编排引擎。
- 保存步骤、参数、工具提示、验证方法和失败处理，不保存内部思维链。
- 提炼和运行使用当前会话、模型及权限；提炼消耗模型额度。复杂会话被压缩后，模型可能不能看到全部早期细节，需人工审核。
- 凭据和个人信息需在保存和导出前检查移除；自动提示不能保证彻底脱敏。
- 目前编辑使用 JSON，旁边提供结构化预览；每次修改递增 revision，防止覆盖并发编辑，不提供历史版本回滚。
- 存储位于当前 Profile 的 workflow-library/library.json；上限 200 个工作流。卸载插件不会主动删除数据。文件为普通 JSON，不是加密密钥库。
- API 只允许本机同源请求，远程分享页面不支持。导入生成新 ID，不覆盖已有记录。
- 安装方式为本地路径依赖，保留本项目目录；搬迁前需要重新安装。修改客户端后运行构建，并重新启用插件或重启 DSH，再刷新原页面。不承诺文件修改自动热更新。

## 本地安装包

npm 包名：`@monster_harryc/dsh-workflow-library`，版本 `0.1.0`。作者：Chi Tianjun（https://github.com/TianjunChi）。许可证：MIT，见 LICENSE。这是第三方插件，并非 DSH 官方产品。当前为待发布版本，尚未发布到 npm 或插件市场。

源码仓库：https://github.com/TianjunChi/dsh-workflow-library（目前私有，非协作者可能无法访问）。

如果已安装旧名称 `dsh-workflow-library`，请先导出重要工作流，并在确认后禁用旧插件再安装新版。两者共享路由、插槽与存储身份，不能同时启用。不要把更换 npm 包名当作自动升级。

使用 DSH 自带插件管理器的本地包安装能力，提供 `.tgz` 文件的绝对路径并确认授权，安装启用后刷新现有 GUI。如果界面没有本地包输入入口，可让 DSH 智能体通过插件管理器安装该绝对路径。不需要解压后运行单独服务器。

已有同名插件时，安装会涉及同一插件的替换，请先导出重要工作流并确认升级操作。此安装包不包含任何用户工作流记录、会话数据、凭据或 DSH 程序本体。运行需要兼容的 DSH 宿主，不是独立应用。

包内仅包含预构建运行文件及说明；以下开发命令适用于原始源码目录，而非解压后的安装包。当前会话已验证本地目录安装；`.tgz` 的完整 GUI 重装验收仍需单独进行。
